## Scope and operating evidence

Candidate note lexical search scores a synchronized derived table and hydrates only the bounded canonical candidates. Ranking, title precedence, source visibility and graph candidate bounds remain the same; [graph preparation](../validation/graph-preparation-109.md) and [full-text evidence](../validation/fulltext-hydration-107.md) retain the unchanged retrieval comparisons and per-workload performance limits.

The maintained OpenClaw fast-notes plugin uses bounded authenticated MCP read-connection reuse, with fresh capture connections and explicit recovery after uncertain writes. Its [dispatch evidence](../validation/openclaw-dispatch-108.md) separates connection, handler, gateway and backend timings; the later [browser supplement](../validation/openclaw-browser-108.md) verifies visible rendering independently. The bundle includes the exact public plugin source, manifests, profiling runner and correctness fixtures. Its JavaScript, manifests, lockfile and tests retain the measured implementation; the README adds guidance to preserve immutable bundles. Installing it in OpenClaw is a separate operator action requiring Node.js 22+ and the documented MCP SDK; the release installer does not install a plugin or change gateway preferences or model selection. Copy the plugin directory to a separate writable working directory or the normal OpenClaw plugin location before running its npm installation or tests. Those commands create `node_modules`; leave the versioned release bundle intact so same-version reinstallation can verify its exact contents.

The [memory refresh guide](../openclaw-memory-refresh.md) describes explicit retained-policy preview and apply; the reviewed [restored-corpus evidence](../validation/extraction-policy-110.md) records the isolated rehearsal and its retrieval-quality limits. Migration requires the exact reviewed private plan digest and owning importer, preserves the last searchable generation until atomic promotion, and leaves unselected/default-false sources unchanged. Models, provider endpoints, permissions and collection defaults are preserved. Ordinary refresh cannot authorize a policy migration.

## Matching installation and recovery

The native asset includes its exact binary and a committed public client/document bundle. The platform-neutral client asset contains matching scripts/docs without a local corpus or native executable. Pin `--version 0.1.0-rc.4` when installing the prerelease; Linux MCP clients can use `--clients-only`. Native macOS Intel/Linux acceptance remains separately tracked in #66. Windows is outside the target scope.

Stop the corpus owner and drain active writes before upgrading. Create and verify a full private portable backup with embeddings and preserve the matching working binary, configuration, credentials, capture journals and registered collection state. Schema 20 adds a migration capability fence; schema 21 adds the derived note search table. Opening the upgraded database with an older binary is refused. Rollback needs the matching old binary plus the pre-upgrade archive restored into a fresh path, and the matching pre-migration collection state. Swapping an old binary against an upgraded database is insufficient.

Plans, exact inputs, credentials, per-source identities and corpus contents stay private. After publication, verify HTTPS checksums and provenance, fresh installation, upgrade preservation and the installed matching clients independently. Record later installation/deployment results separately from sealed BUILDINFO; never replace assets to change validation status.
