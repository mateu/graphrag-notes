# GraphRAG Notes 0.1.0-rc.4

This candidate prepares a matching server/client bundle for the performance and retained extraction-policy follow-ups #106–#110. The published [rc.3 prerelease](https://github.com/mateu/graphrag-notes/releases/tag/v0.1.0-rc.3), its tag and all assets remain immutable. Candidate packaging, publication, installation and deployment have separate validation records; this preparation document does not assert that they have run.

## Scope and operating evidence

Graph preparation reuses the bounded lexical prefix already obtained for hybrid fusion, removing its second full-text scan. Note lexical search scores a synchronized derived table and hydrates only the bounded canonical candidates. Ranking, title precedence, source visibility and graph candidate bounds remain the same; [graph preparation](../validation/graph-preparation-109.md) and [full-text evidence](../validation/fulltext-hydration-107.md) retain the unchanged retrieval comparisons and per-workload performance limits.

Exact vector retrieval retains its production path. Diagnostic candidates improved warmed medians and p95 but introduced larger early maxima; #106 remains open with a reproducible engine-tail follow-up. Those candidates introduce no runtime table, approximate search, model change or concurrency increase in this release.

The maintained OpenClaw fast-notes plugin uses bounded authenticated MCP read-connection reuse, with fresh capture connections and explicit recovery after uncertain writes. Its [dispatch evidence](../validation/openclaw-dispatch-108.md) separates connection, handler, gateway and backend timings. Gateway protocol events do not imply a completed visible-browser acceptance check. The plugin remains independently installed; the client bundle does not change gateway preferences or model selection.

The [memory refresh guide](../openclaw-memory-refresh.md) describes explicit retained-policy preview and apply, with [restored-corpus evidence](../validation/extraction-policy-110.md). Migration requires the exact reviewed private plan digest and owning importer, preserves the last searchable generation until atomic promotion, and leaves unselected/default-false sources unchanged. Models, provider endpoints, permissions and collection defaults are preserved. Ordinary refresh cannot authorize a policy migration.

## Matching installation and recovery

The native asset includes its exact binary and a committed public client/document bundle. The platform-neutral client asset contains matching scripts/docs without a local corpus or native executable. Pin `--version 0.1.0-rc.4` when installing the prerelease; Linux MCP clients can use `--clients-only`. Native macOS Intel/Linux acceptance remains separately tracked in #66. Windows is outside the target scope.

Stop the corpus owner and drain active writes before upgrading. Create and verify a full private portable backup with embeddings and preserve the matching working binary, configuration, credentials, capture journals and registered collection state. Schema 20 adds a migration capability fence; schema 21 adds the derived note search table. Opening the upgraded database with an older binary is refused. Rollback needs the matching old binary plus the pre-upgrade archive restored into a fresh path, and the matching pre-migration collection state. Swapping an old binary against an upgraded database is insufficient.

Plans, exact inputs, credentials, per-source identities and corpus contents stay private. After publication, verify HTTPS checksums and provenance, fresh installation, upgrade preservation and the installed matching clients independently. Record later installation/deployment results separately from sealed BUILDINFO; never replace assets to change validation status.
