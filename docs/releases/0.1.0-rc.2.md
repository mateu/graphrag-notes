# GraphRAG Notes 0.1.0-rc.2

The [published `v0.1.0-rc.2` prerelease](https://github.com/mateu/graphrag-notes/releases/tag/v0.1.0-rc.2) is the daily-use validation candidate for [#64](https://github.com/mateu/graphrag-notes/issues/64), completing the local daily-workflow phase of [#55](https://github.com/mateu/graphrag-notes/issues/55). It was published on 2026-10-03 UTC after review and merge. The existing `v0.1.0-rc.1` release remains the historical onboarding baseline; its assets are never replaced.

The candidate adds guarded search-result inspection and explicit source opening, provider-free keyword search, named one-shot folder sync with resumable work and confirmed pruning, multiline capture and revision-guarded note editing, raw cited augmentation output, a proposal review inbox, and a persistent terminal workspace. These commands preserve the existing hybrid retrieval ranking and explicit graph review policy. Network MCP access remains a follow-up in [#56](https://github.com/mateu/graphrag-notes/issues/56).

## Candidate platform and contents

The initial candidate is a native **macOS Apple Silicon** archive for **macOS 15 or newer**. Intel macOS and Linux native builds/walkthroughs remain deferred to [#66](https://github.com/mateu/graphrag-notes/issues/66). The future stable-tag workflow retains all three targets; this candidate does not imply those other platform assets were tested or published.

The published assets are:

- `graphrag-notes-v0.1.0-rc.2-aarch64-apple-darwin.tar.gz`
- `SHA256SUMS`
- `BUILDINFO.json`

The archive contains exactly `graphrag` and `samples/first-notes.md`, both regular files. It contains no configuration, database, credentials, models, or build metadata. The installer verifies the archive checksum, refuses an existing binary unless `--force` is explicit, and preserves edited starter notes. Configuration creation remains a separate `init --write` action.

`BUILDINFO.json` records the final commit and tree, the build commit and tree, compiled-input identity, binary/sample/archive hashes, exact workspace package versions, native target, Rust toolchain, deployment target, runtime libraries and validation states. Metadata and the archive are both listed in `SHA256SUMS`. An omitted or deferred validation is recorded explicitly; a local transport test is never presented as a published HTTPS download.

## Install the published prerelease

Download the exact version's installer, inspect it, then install the candidate. The [source workflow](../getting-started.md#build-from-source) remains available for development, Intel Macs, and Linux.

```bash
curl -fsSL https://raw.githubusercontent.com/mateu/graphrag-notes/v0.1.0-rc.2/scripts/install.sh -o /tmp/graphrag-install.sh
bash /tmp/graphrag-install.sh --help
bash /tmp/graphrag-install.sh --version 0.1.0-rc.2
export PATH="$HOME/.local/bin:$PATH"
graphrag --version
```

The version command must report `graphrag 0.1.0-rc.2`. GitHub's latest-stable lookup excludes prereleases, so this candidate requires the explicit `--version`. For a new configuration, follow the `init --backend ollama` preview and write steps in [getting started](../getting-started.md). For an existing configuration, run plain `graphrag init`. Verify a portable backup before [upgrading with `--force` or choosing a separate binary directory](../getting-started.md#upgrade-an-existing-installation). See [the daily workflow](../daily-workflow.md) for repeatable tasks.

## Data compatibility

Back up an existing database before upgrading. This source generation includes schema migrations through version 15; the older onboarding binary cannot open a database upgraded beyond its supported schema. A downgrade requires an appropriate pre-upgrade portable archive restored into a fresh database path. Portable backups omit local file URIs and model vectors by default; restored content remains searchable with keyword mode, but local file reopening requires restoring/reimporting host-local provenance. These privacy and compatibility rules are unchanged.
